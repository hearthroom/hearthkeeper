# 0.2 回報流程交付範圍

需求是完成填表、社管處理、結案留檔，而非一次完成 V1.0 的所有社群管理功能。

## 可驗收流程

- `/hearthkeeper` 或 `/feedback` 選匿名或顯示帳號的私密回報，再填標題及內容。
- 案件先存入 SQLite，再透過持久發送工作轉到部署者核准的私人論壇。
- `/myreports` 只顯示操作人的案件，可分頁查看完整紀錄、補充、申請結案或重開。
- 授權社管從論壇的「處理案件」或 `/cases` 認領、回覆、要求補充、結案、重開或拒絕申請。
- 論壇一般聊天是內部討論；只有專用表單會成為對外回覆。機器人不接收一般聊天事件。
- 結案先存處理結果，再鎖定與封存帖子；同步失敗時仍可查詢案件與結果。

本版本提供一般問題與建議的回報流程。檢舉、申訴的獨立敏感承辦組、通知身分組、
處分、跨站整合及私訊通知仍屬後續功能，不會假裝提供尚未完成的操作。

## 安全與失敗處理

案件論壇只允許部署指定角色與 bot 檢視；Discord Administrator 與伺服器擁有者仍可繞過限制。
每次對論壇寫入前都重新讀取頻道、角色及 bot 權限，發現其他成員／角色讀取覆寫即拒絕發送。
角色名單只在部署環境設定，不可由 Discord 表單自行修改。社管操作重新讀取當前成員角色。
匿名文章由 bot 獨立發送，不含原互動的發起人 metadata；使用者自填文字仍可能透露身分。

身分查詢使用 guild-scoped HMAC；帳號映射及受限操作人稽核使用 AES-256-GCM。
兩把金鑰不得相同；金鑰或 guild 與既有資料不符時拒絕啟動，不能悄悄建立新索引。
模式送出後不可變更。普通日誌與 metrics 不包含身分、案件編號或案件內容。

案件寫入、事件、操作去重在同一 SQLite 交易中完成。案件操作有版本檢查，舊表單不會覆寫新狀態。
成員每 60 秒可建立一案，最多 3 個未結案案件；補充和狀態申請每 5 秒一次。
按鈕使用隨機伺服器端操作代碼；成員操作綁定本人、guild 和版本，過期後重新查案。
社管共用帖子入口仍須即時角色檢查，不能把代碼當作存取權。

發送前先標記 sending；程序中斷後，透過 bot 自己的帖子／訊息標記讀回。
Discord 回傳結果未知且找不到可證明的發送結果時，保留 pending，停止盲目重送並透過 metrics 告警。
維運者須核對 Discord 上的紀錄後才能手動處理未知工作；0.2 沒有一鍵強制重送工具。
讀回最多 2,000 個封存帖子或訊息，超過範圍即停止，不把不完整搜尋當作「未發送」。

結案 90 天後清除本地案件、身分、事件與操作代碼，並重試刪除論壇帖子。
外部刪除清單只保留定位，不保留正文；另外寫入獨立 JSONL 清除清單供備份恢復前重播。
SQLite secure_delete 已啟用；SQLite 的舊 WAL／磁碟快照仍屬需受限保存的備份資料。
部署者須將加密備份保存期限限制為 30 天並分開保管金鑰；本版不自動建立備份或配置遠端備份服務。
恢復資料庫前，必須保留最新清除清單，不可拿舊快照一起覆蓋它。

## 技術與驗證決策

Node.js 24 的內建 SQLite（仍有實驗性 API 標記）避免額外 native-addon 安裝；固定 runtime 版本。
資料檔放在 systemd StateDirectory，服務採單實例，程式目錄唯讀。
繁體中文與英文是本 Discord 專案支援語系，其餘語系回退英文；不翻譯回報正文。
MCP 不適用：此版本是 Discord 內的案件服務，不開放外部案件 API 或 AI 客戶端存取。

新增監控：

- `hearthkeeper_case_delivery_total{outcome="success|failure"}`：同步嘗試結果 counter。
- `hearthkeeper_case_pending`：目前等待同步的案件 gauge（最多一批 20 案的工作讀回）。
- `hearthkeeper_case_forum_ready`：論壇安全檢查 gauge；值為 0 時不能視為案件服務可用。

驗證：`hearthkeeper_case_forum_ready == 1`、`hearthkeeper_case_pending == 0`，
以及 `increase(hearthkeeper_case_delivery_total{outcome="failure"}[15m])`。
`/readyz` 只代表 Discord Gateway 和設定的 guild 可用，案件論壇狀態另由上述指標判斷。
測試覆蓋真實 SQLite、授權拒絕、去重、版本競爭、匿名邊界、長文、保存期限與未知發送恢復。
實際 Discord 驗收另須確認：表單收據、匿名帖子、對外回覆、成員查案和帖子 locked/archived。

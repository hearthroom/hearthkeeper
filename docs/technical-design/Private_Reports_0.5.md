# 0.5 私密回報對話

本版本在已配置的專用文字頻道建立每案私人討論串；提案人與社管直接交談、傳附件，一般成員看不到其他人的案件。社管可以辨識提案人的 Discord 帳號。原社管論壇仍維持隱藏，不授予提案人論壇權限。

## 啟用與權限

`CASE_PRIVATE_PARENT_ID` 是專用 **一般文字頻道**，不能填論壇 ID。未設定時不建立私人串，維持原本代轉；設定後新私密回報才建立私人串，既有具名／匿名案件均不自動轉換。

| 對象 | 專用文字父頻道權限 |
|---|---|
| @everyone | 明確允許查看、讀取歷史、在討論串發言、附加檔案；明確拒絕在父頻道發言、建立公開／私人討論串、管理討論串 |
| 原核准社管角色 | 允許查看、歷史、討論串發言、附件、管理討論串 |
| Hearthkeeper | 允許查看、歷史、傳送訊息、討論串發言、附件、嵌入連結、建立私人串、管理討論串 |

父頻道只放入口說明；個案內容不寫在父頻道。bot 檢查父頻道類型、所屬伺服器、所有 overwrite、核准角色與本人實際權限，然後建立 `invitable=false` 的私人串，只自動加入提案人。社管以父頻道 Manage Threads 查看及承辦，不批次列舉全群會員。未要求 Administrator、Manage Channels 或新的特權 intent。

Discord 管理員與具 Manage Threads 權限的人仍能查看、邀請其他人；這是 Discord 管理權限的既有能力。若社管自行加入串，卸任時管理員須一併移除其討論串會員資格；本版沒有全量會員清查，不把移除社管角色宣稱為清除所有私人串邀請。

## 使用與狀態

1. `/hearthkeeper` → 六個分類 → 預設「提出私密回報」→ 標題、內容。
2. 表單先保存，私人串尚未準備好時顯示提示；「更新進度」會重新讀取案件，準備好才出現「開啟私人對話」。容量／權限不足期間仍可用「我的回報」補充，不丟案件。
3. 私人串顯示使用者標題，首則內容以日期開頭；社管在兩種案件對話回覆都能將初始狀態改為處理中。一般對話及 Discord 附件留在私人串，不抄錄全文、不讀 Message Content；正式補充、對外回覆與結案理由仍走案件按鈕。
4. 社管「貼文管理」的狀態、關閉、鎖定、恢復／重開同步到論壇及私人串。私人串因閒置自動封存不等於業務結案。
5. 既有匿名代轉繼續可用；匿名案件絕不自動加入提案人或建立具名對話。

## 一致性與留存

SQLite 新增 `private_projections`、`private_events`、`private_deletions`，不重用既有論壇 thread_id／投遞游標。每案保存建立時 parent ID，變更新案設定不改既有案件的目的地。

建立先使用非個資的暫時辨識名稱，持久保存外部 ID 後才發內容、改成使用者標題與邀請本人；這個階段一般成員尚不可見。建立／發送逾時先讀回 bot 擁有的私人串或訊息標記；找不到可確定的結果時保留待處理，不盲目重建。每批最多處理 20 件並輪替，避免少數未知工作擋住新案件。

對外事件使用獨立 receipt，內部狀態理由與管理備註不轉送。成員資格、名稱及關閉／鎖定都有實際讀回，成功 API 回應不足以標示同步完成。程序每 15 秒輪替檢查私人串狀態；API 限速按 SDK 退避。

結案後 90 天清理，論壇、私人串先記入同一筆 flush 的外部刪除紀錄，再移除本機案件；兩種外部刪除分別重試，找不到頻道視為已刪。還原備份時先重播此清單；不可只還原資料庫而丟掉清單。尚未找回的模糊建立工作保留追蹤，避免刪掉唯一線索後留下無法清理的串。Discord 附件隨原訊息／串處理，不承諾外部 CDN 或他人已下載副本立即消失。

`CASE_PRIVATE_MAX_ACTIVE` 預設 100，範圍 1–500，保護 bot 可見的全群活躍討論串容量；它不是 Discord 官方配額數字。私人串不占一般頻道名額，但仍有活躍限制。滿額時不開始建立，表單與論壇照常處理。

## 驗證與發布

完整可信集是 `npm run check`；測試涵蓋權限拒絕、匿名隔離、跨人查詢、模糊重試、內部事件隔離、雙投影結案及重開、容量阻擋、持久刪除與名稱讀回。

正式啟用還需用一般成員 A／B 與社管驗證：A 看得到自己私人串、可發言傳附件；B 看不到也不能用連結存取 A；社管能處理；PASS 後串已封存且鎖定；匿名案件仍不暴露帳號。未做此驗證不能宣稱 Discord 實際旅程已驗收。

回滾：只移除新案啟用設定可停止建立新私人串，0.5 仍處理舊串投遞及清理；不要直接退回不理解私人投影／多目標清除紀錄的舊版，否則關案與清理會漏掉私人串。更新前保留一致備份及原身分金鑰。

## 可觀測性與 MCP

- `hearthkeeper_case_private_delivery_total{outcome}`：counter，outcome 僅 success／failure／capacity，在投遞、清理與容量阻擋處計數。
- `hearthkeeper_case_private_pending`：gauge，待同步案件總數。
- `hearthkeeper_case_private_ready`：gauge，已設定的私人入口通過權限與狀態檢查時為 1；未啟用時為 0。
- 讀回：loopback `/metrics`；PromQL `hearthkeeper_case_private_pending`、`increase(hearthkeeper_case_private_delivery_total{outcome="failure"}[15m])`。不加入使用者、案件或頻道 ID labels，不記錄正文／附件或原始 SDK 錯誤。
- MCP 不適用：本版只增加 Discord 互動與私人串，未新增 HTTP 管理 API，也未建立網站會員授權；網站案件橋接屬社群整合的後續階段。

[Discord Threads](https://docs.discord.com/developers/topics/threads) 說明私人串權限、封存與容量；[Channel API](https://docs.discord.com/developers/resources/channel) 說明建立及會員管理。

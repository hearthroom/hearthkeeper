# 0.3 分類、狀態標籤與貼文管理

本版延續 [0.2 回報流程](Feedback_0.2.md) 的身分、儲存、保存期限與權限邊界。
六個入口依序為功能異常、儲值問題、帳號問題、角色卡錯誤、審核疑問、角色卡檢舉。
選分類後選匿名／顯示帳號，再填標題與內容。分類持久保存，不能由貼文操作改變。
檢舉與審核疑問仍交給同一組核准社管，沒有獨立敏感承辦組或自動處分。

## 狀態與通知

新案使用「🔵 等待中」；社管／技術人員回覆後改為「⚪ 處理中」，需要技術接手則由社管選「🟠 等待中（技術）」。
要求成員補充仍使用「待補充」，結案改為「已結案」。Discord 不支援任意標籤底色，以彩色圓點呈現。
每次同步保留案件分類並替換狀態標籤。以論壇標籤顯示狀態，不額外依賴表情反應。
開案只提及設定的社管角色；後續回覆及重新同步不重複提及。Discord 個人通知設定仍決定是否收到推播。
缺少任一必要標籤或角色提及權限時，外部發送前的檢查失敗；已收表單仍留在資料庫等待處理。

## 第二個管理面板

案件首則訊息與社管案件詳情都有「貼文管理」，同時提供藍／白／橙三種狀態選項。每次操作重新核對社管角色、版本並填處理理由。

| 操作 | 貼文關閉 | 貼文鎖定 | 案件狀態 |
|---|---|---|---|
| 關閉貼文 | 是 | 保留 | 不變 |
| 鎖定貼文 | 保留 | 是 | 不變 |
| 關閉並鎖定 | 是 | 是 | 不變 |
| 恢復貼文 | 否 | 否 | 不變 |

Discord 的鎖定限制一般成員重新開啟，並不禁止開啟中貼文的回覆。結案會同時關閉與鎖定；
已結案案件須用「重開案件」，不能只恢復貼文。管理理由留在社管紀錄，不提供給成員。
回覆表單與案件貼文中的核准社管一般訊息都會觸發白色處理中；成員補充保留原本佇列狀態（待補充則回到藍色等待中）。
沿用既有核准角色，不另外新增技術角色。只訂閱非特權 GuildMessages 事件，核對案件貼文及作者的最新角色；
不讀取、記錄或代轉原訊息正文與附件，也不重新開啟已結案案件。離線期間的訊息不回補，社管可用面板校正狀態。
目前服務只管理機器人建立且持久追蹤的案件，不操作任意論壇貼文。

## 私密對話邊界

論壇貼文繼承父頻道權限，不能把同一隱藏論壇逐帖開給不同回報人。
本版仍為匿名／具名代轉：成員用表單補充和查詢，論壇只供社管；沒有開放直接對話或附件。
若要成員與社管直接發言、傳附件，須另外採每案私人文字頻道等隔離方式，且社管會看得到帳號。

## 驗證與營運

SQLite 採新增欄位升級，舊案例與加密對應保留；舊結案資料維持關閉並鎖定。
測試包含六類入口、分類持久化、社管授權、四種貼文動作、成員不見管理理由、
舊 schema 升級、Discord 分類／狀態替換與鎖定封存讀回。完整可信集為 `npm run check`。
真實 Discord 仍須另外驗收新案分類與提及、狀態變化、管理面板及權限隔離。
MCP 不適用：這是限定 Discord 社群的案件互動，沒有對外服務 API。
沿用 `hearthkeeper_case_forum_ready`、`hearthkeeper_case_pending` 與
`hearthkeeper_case_delivery_total{outcome}`；標籤或提及能力缺失歸入論壇未就緒，
同步失敗增加 failure counter，不新增含角色或案件 ID 的標籤。

## 0.3.1 貼文標題與日期

成員填標題、內容並提交後，論壇標題直接採用表單標題。首則訊息以
「YYYY-MM-DD HH:mm（UTC+8）｜內容」開頭，社管提及放在末尾，列表預覽能先看見內容。
日期使用持久保存的原始提交時間，不會在重試或重新同步時變成今天。正文保留成員輸入的 Discord 格式；
停用連結預覽及非核准角色的提及解析。管理面板仍可查到案件短編號。

同名標題不當成案件識別。建帖中斷的恢復，核對 bot 擁有的首則訊息與資料庫保存的共用面板代碼；
這項唯讀比對不授予任何操作權限，也不受 UI 代碼過期影響。舊版本的完整編號標題仍可恢復。
既有案件同步會更新標題與首則訊息，保留原本分類、狀態、封存與鎖定結果，不重複通知社管。

完整可信集 `npm run check` 包含同名案件恢復、舊格式相容、原始日期、長正文與狀態保留。
MCP 不適用，仍是 Discord 內的既有案件呈現。沿用案件同步成功／失敗、待同步及論壇就緒指標。

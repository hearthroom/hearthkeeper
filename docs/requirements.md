# Hearthkeeper 產品需求

> 版本：V1.0 · 日期：2026-09-20 · 維護者：Hearth Room
> 來源：專案發起人確認的「Discord 社群服務選單、表單回報、社管論壇留檔」提案。

本文件讓社管與開發者對齊第一版範圍。Hearthkeeper 要解決的問題是：
回報散落在聊天與私訊中，成員不知道進度，社管也難以交接。
成功的第一版應能完成提出、認領、補充、回覆、結案與重開的完整流程。

## 使用者與目標

| 使用者 | 想完成的事 |
|---|---|
| 新成員與玩家 | 找到指南、選擇通知、提出問題、查詢處理結果 |
| 作者 | 找試玩者、取得寫卡說明、提出作品相關問題與申訴 |
| 承辦社管 | 分類、認領、回覆案件；分清內部備註與對外回覆 |
| 敏感案件處理者 | 處理檢舉、社管爭議與申訴，限制可見範圍 |
| 部署維運者 | 自行部署、備份、恢復，保護身分對應與憑證 |

## 版本範圍

| 階段 | 功能 | 完成條件 |
|---|---|---|
| M1 | 服務選單、指南、通知身分組 | 手機與桌面皆可使用；只可領取指定的通知身分組 |
| M1 | 匿名代轉與我的回報 | 社管帖子不含帳號；成員僅可讀寫自己的案件 |
| M1 | 私密回報 | 使用同一代轉流程，但在送出前告知承辦社管會看見帳號 |
| M1 | 社管認領、回覆、結案與重開 | 內部備註不送出；處理結果與狀態可追蹤 |
| M1 | 警告、限時禁言與申訴 | 人工確認、有理由、權限檢查及結果讀回 |
| M1 | 防重送、冷卻、開單上限 | 重複互動不重開案件；限額拒絕不丟失已送出的案件 |
| M1 | 創作支援入口 | 寫卡、匯入、Lorebook 指南與試玩回饋模板可設定 |
| M2 | 公開建議 | 投稿人確認公開版本後才發布；只支持建議類案件 |
| M2 | 角色卡預覽、作者綁定與更新通知 | 只讀公開且可展示的作品；綁定可撤回 |
| M2 | 審核提醒 | 導回社群站操作，不從 Discord 擴大站內權限 |
| M3 | 活動、徵稿與投稿整理 | 報名、截止提醒與結果公布可追蹤；獎勵另行設計 |

私人工單頻道或私人討論串是後續可選的直接對話模式；M1 統一採表單代轉。
這樣保留私密回報能力，也避免同時維護兩套訊息入口。
機器人不重做 Discord 的一般防洗版系統；安裝說明會引導搭配原生 AutoMod。

## 不可改變的邊界

1. 匿名代轉只隱藏系統提供的帳號識別。成員自行寫出的名字、連結可能暴露身分。
2. 機器人保存帳號對應，以便查案與雙向回覆。維運者與 Discord 不在匿名承諾之外。
3. Discord 管理員可繞過頻道限制；不能向成員承諾對伺服器擁有者保密。
4. 提案人不加入社管論壇。論壇文章不能當作逐案獨立的權限容器。
5. 站內私有角色設定、聊天紀錄、點數與付款憑證不進入機器人。
6. 第一版不自動發布 GitHub Issue、不收費、不自動裁定爭議，也不提供 AI 聊天。
